## Objective

Initialize the `dbt` (data build tool) project for the Market Intelligence Hub and develop the foundational `staging` models. These models will read raw data ingested from our extractors (theoretically stored in BigQuery) and perform basic cleaning, renaming, casting, and standardization, acting as the foundation for our analytical marts.

---

## Architecture

We follow standard dbt best practices:
- **`sources`**: The raw tables in BigQuery where our Loaders (to be built in M3) will dump data.
- **`staging`**: `stg_<source>__<entity>.sql` — 1:1 mapping with source tables. Handles type casting, renaming to `snake_case`, and basic deduplication.

## Design Notes
- As we are using BigQuery, nested JSON fields from the raw API responses might be loaded directly. Staging models are responsible for unnesting them if required by canonical schemas.
- We implement staging *before* the BigQuery loader (Issue #12) to establish the explicit target schema contract that the loader must satisfy when inserting data into the warehouse.
